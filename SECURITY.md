# Security policy

## Reporting a vulnerability

Send exploitable details, credentials, personal data and diagnostic logs through the private security contact listed on the [SingLinkVPN website](https://singlinkvpn.com/).

For a suspected vulnerability, include the information needed to reproduce the issue safely. For a documentation or metadata correction, open a [repository issue](https://github.com/SingLinkLabs/SingLinkVPN/issues).

Useful reports include the affected product and version, operating system, reproducible steps, expected and observed behaviour, and a note identifying sensitive attachments. Redacted logs help the team review reports efficiently.

## Published security evidence

The following repositories provide signed reports, integrity records, tested versions and reference dates:

- [Desktop 2.5 security-audit evidence](https://github.com/SingLinkLabs/singlinkvpn-security-audit)
- [2026 no-logs verification evidence](https://github.com/SingLinkLabs/singlinkvpn-no-logs-report)

## Authorized research

Security research on accounts, production services or third-party systems requires written authorization. Testing builds and systems you own remains the recommended starting point.
